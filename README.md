# 侦探档案馆

“侦探档案馆”现定位为纯微信公众号内容项目：用原创文章、人物档案、案件导读、书单和互动选题，整理经典侦探及其作品。

当前方向不再建设或部署小程序、API、社区和线上数据库。公众号文章、配图、资料来源及公共目录数据全部跟随 Git 版本管理；数据库备份仅在仓库外留档，禁止提交。

## 日常工作流

### 1. 编辑稿件

每篇文章使用 Markdown 保存，配图放在文章对应的 `assets/` 目录。稿件开头保留标题、摘要、封面、栏目、状态和预计阅读时间等元数据。

### 2. 内容检查

```bash
npm run check
```

默认检查只覆盖当前公众号产品：

- 稿件元数据、标题唯一性和正文完整性；
- 本地配图路径及文件存在性；
- 资料来源、阅读入口和版权/原创说明；
- 公共目录批次是否完整保存在 Git；
- 环境文件、数据库归档和生成的 DOCX 是否误入 Git。

### 3. 生成微信公众号导入版

```bash
python -m pip install -r tools/requirements-wechat-docx.txt
npm run build:wechat
```

默认输出到 `content/wechat/publish/`。该目录是可重复生成的本地产物，不提交 Git。详细说明见 `tools/README-wechat-docx.md`。

### 4. 人工发布

DOCX 导入微信公众号后台后，仍需人工完成手机预览、封面裁切、链接检查、版权复核和最终发布。发布后更新文章状态，并按 7 天窗口记录送达、读完、收藏、转发、在看、留言和新增关注数据。

## 数据边界

适合进入 Git：

- 侦探、作品、图鉴和推荐关系；
- 文章正文、资料来源、编辑状态和发布计划；
- 原创配图、经确认可使用的素材及生成记录。

不得进入 Git：

- 数据库 `.dump`、加密归档及校验边车；
- 用户身份、微信 OpenID、会话、评论、书架和访问日志；
- AppSecret、数据库密码、后台密码、上传密钥和其他令牌。

完整公共目录的历史数据仍保存在 Git 跟踪的 JSON 与 33 个不可变批次中，不依赖云数据库作为内容事实来源。

## 项目结构

```text
content/wechat/        当前公众号稿件、配图与生成记录
tools/                 Markdown → 微信公众号 DOCX 工具
docs/                  公众号产品、选题和编辑说明
apps/api/              历史 API 实现，仅保留参考
apps/miniprogram/      历史小程序实现，仅保留参考
database/              历史数据库结构，仅保留参考
ops/                   历史部署工具，仅保留参考
```

历史应用代码不再属于当前发布链路。需要验证历史实现时可手动执行：

```bash
npm run check:legacy-app
```

该命令可能需要 PostgreSQL、Docker 和历史环境配置；日常公众号写作不需要运行。

## 品牌与内容原则

- “侦探档案馆”是独立原创内容品牌，不宣称与《名侦探柯南》官方有关联。
- 不使用未经授权的漫画、动画、影视截图、译文或有声内容。
- 人物和作品名称仅用于评论、介绍、研究和阅读索引。
- 优先使用出版社、作者官网、公共图书馆及其他权威来源核验事实。
- 不在标题、摘要和无警告正文中泄露凶手、核心诡计或关键身份。
- AI 只辅助原创视觉和原创案件，发布时记录工具、生成环节和人工修改范围。
