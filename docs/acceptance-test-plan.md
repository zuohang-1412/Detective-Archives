# 侦探档案馆 MVP 验收测试方案

版本：v1.2

验收基线：`codex/mvp-release`

设计日期：2026-07-22

## 1. 验收范围分析

本轮验收覆盖公开档案与作品、微信身份、个人书架、评价社区、内容治理、运营后台、安全基线、数据一致性和部署运维。AI 视频属于 PRD 明确的第二阶段，不作为 MVP 发布阻塞项。

核心对象包括 `users`、`user_sessions`、`detectives`、`works`、`work_links`、`shelf_items`、`reviews`、`comments`、点赞、`reports`、`moderation_records` 与 `audit_logs`。角色覆盖游客、普通用户、内容编辑 `EDITOR`、审核员 `MODERATOR` 和管理员 `ADMIN`。

重点状态链：

- 作品：`DRAFT → PENDING_REVIEW → PUBLISHED → HIDDEN/ARCHIVED`。
- 书架：`WISHLIST / IN_PROGRESS / COMPLETED / PAUSED / DROPPED`，完成态进度必须为 100%。
- 评价与回复：`PENDING_REVIEW → PUBLISHED / REJECTED / HIDDEN`，已发布内容编辑后回到待审。
- 举报：`OPEN → PROCESSING → RESOLVED / REJECTED`，重复结案不得成功。
- 账号：有效 → 退出/会话撤销 → 注销去标识化。

外部依赖包括微信 `code2Session`、真实小程序 AppID、HTTPS 域名、托管 PostgreSQL、Caddy/Docker 运行环境、正版渠道站点和微信平台审核。自动化环境可以替代微信身份交换，但不能替代真机登录与正式提审。

## 3. P0 详细测试用例

### AT-P0-01 存活与数据库就绪

- 前置条件：API 已启动；分别准备可用和不可用数据库连接。
- 步骤：请求 `GET /health`、`GET /ready`；再断开数据库并重试 `/ready`。
- 预期：存活检查始终返回服务名；数据库可用时 `/ready` 为 200，故障时为 503 和稳定错误结构；响应带 `x-request-id`、`cache-control: no-store`，正文不含主机、密码或 SQL。
- DB：正常场景执行 `SELECT 1`。
- 清理：恢复数据库连接。

### AT-P0-02 侦探与图鉴发现链路

- 入口：首页、档案室、侦探详情。
- 步骤：访问侦探列表、按“波洛”搜索，组合国家/时代/分类/人物类型/标签并逐页加载全部结果，访问 `sherlock-holmes`；查询图鉴 1～108 卷、`PB-004-STD`、`PB-105-SP`、扩展目录与历史人物，从已映射推荐进入正式作品；提交 `page=0` 和不存在 slug。
- API：`GET /api/v1/detectives`、`/picture-book`、`/archive-directory` 及各详情接口。
- 预期：生产 DB 返回 150 位人物、143 部作品、109 条图鉴（108 标准版+1 特装版）、41 条扩展/历史目录记录；73 条已提取原始推荐全部返回正式目标标题和作品 slug 并可进入正版渠道；已发布人物无待补证状态；分页不超过 50；错误分别为 400/404 且错误码稳定。
- DB：公开结果只来自 `status='PUBLISHED'`，不存在孤儿来源关系；已映射推荐均指向有启用正版入口的正式作品。

### AT-P0-03 作品与正版链接

- 步骤：查询作品列表和代表作品详情；打开详情后停用其中一条测试链接，再从原页面尝试复制；对全部启用链接执行安全校验和在线巡检。
- API：`GET /api/v1/works`、`GET /api/v1/works/:slug`。
- 预期：详情包含侦探、创作者、简介和链接；仅 `is_active=true` 且 HTTPS 的链接返回；复制前服务端再次确认，停用后返回 404、停止操作并提示提交反馈，不回退缓存旧地址；不存在作品为 404。
- DB：`works` 与 `work_links` 状态和公开 API 一致；操作后审计日志存在。
- 人工复核：构造自动巡检无法确认、超过 90 天和确认 404 三类入口；确认有效后前两类在 90 天内离队，确认 404 仍重新入队；两路重复确认只写一条审计，确认失效原子停用，重新启用清空旧健康证据并等待新巡检。
- 安全：`EDITOR` 不能登记最终人工结论；证据引用中的访问令牌、签名、私钥或内联内容必须拒绝。

### AT-P0-04～05 登录、协议与会话

- 数据：同一模拟微信 subject，另一个独立 subject。
- 步骤：不传协议同意登录；同意后登录两次；并发提交相同 code；访问 `/auth/me`；退出后复用旧令牌。
- API：`POST /auth/wechat`、`GET /auth/me`、`POST /auth/logout`。
- 预期：未同意为 400；同身份和并发请求映射到同一 user ID；服务端只保存令牌哈希；退出后旧令牌为 401。
- DB：`user_identities` 外部身份唯一，`terms_accepted_at`、`privacy_accepted_at` 非空。

### AT-P0-06 个人书架

- 步骤：用户 A 连续两次 PUT 同一作品为 `WISHLIST`，再改为 `COMPLETED`；用户 B 查询同作品；管理员隐藏另一部已收藏作品，用户 A 查询、尝试更新并移除；恢复作品。
- API：`PUT/GET/DELETE /api/v1/me/shelf/:workId`，`GET /api/v1/me/shelf?status=COMPLETED`。
- 预期：重复 PUT 返回同一记录；完成态进度 100%、完成时间非空；用户 B 返回 `null`；隐藏作品公开详情 404，但私人记录保留并返回 `isAvailable=false`，更新为 404、删除为 204。
- DB：`(user_id, work_id)` 唯一且 UI/API/DB 状态一致。

### AT-P0-07～10 社区主链路

- 步骤：创建带剧透短评和有标题长评；重复同类型评价；游客查询；审核员发布；用户 B 点赞两次、回复、选择原因并填写补充说明后举报两次；发布回复；作者编辑评价再删除；尝试由他人删除。
- API：作品评价、评价详情、评论、点赞、举报和后台审核接口。
- 预期：新内容为 `PENDING_REVIEW` 且游客不可见；发布后可见；拒绝后为 `REJECTED`、不能直接恢复，作者修改后重新待审；重复评价/举报为 409；点赞数只增加 1；他人删除返回 404；删除后正文不公开。
- UI：带剧透正文和回复默认显示遮罩，点击后才展示；举报面板必须选择原因，补充说明可选且最多 500 字，提交中不可重复操作。
- DB/审计：评价、回复、举报、审核、删除均有正确状态；关键写操作有请求 ID。

### AT-P0-11～13 后台与治理

- 角色：EDITOR 只能维护草稿并提交审核；MODERATOR 只能治理用户内容；ADMIN 可以发布目录和管理治理动作。
- 步骤：创建作品草稿、提交 `PENDING_REVIEW`、管理员发布/隐藏；新增并停用 HTTPS 链接；审核评价、处理举报、限制普通用户；分别用错误角色调用接口。
- 预期：理由少于 2 字为 400；无权限为 403；编辑不能直接发布；审核员不能维护目录；处置后用户查询账号状态为 200 并返回限制信息，书架和链接反馈等普通写入为 403，数据导出、会话轮换、退出和注销仍可用。
- 分页：审核、举报、作品、侦探、用户、审计和链接反馈单页最大 50；请求 51 返回 400，运营台可读取后续分页且总数不被固定上限截断。
- DB：`moderation_records` 和 `audit_logs` 记录操作者、动作、对象、理由/元数据、请求 ID 和时间。

### AT-P0-14 数据导出与账号注销

- 步骤：正常用户导出数据；检查响应头、JSON 结构和敏感字段；将另一用户限时限制后再次导出并轮换会话；高频导出；最后缺少确认字段调用注销、确认注销、复用旧令牌，并查询用户、身份、会话、书架、书架事实、活跃日、点赞和个人内容。
- 预期：导出为 `no-store` 的 JSON 附件，包含账号、身份、书架、本人评价/回复、互动、举报/申诉、链接记录、活跃日、AI 任务及与本人相关的审核/审计；不包含 Bearer/会话 ID/令牌哈希、审核员身份或内部处置备注；受限用户仍能导出和轮换数据权利会话，普通写入为 403；每小时超过 3 次为 429；每次成功导出写 `DATA_EXPORT` 审计。缺注销确认 400；成功 204；旧令牌 401；用户去标识化并停用，身份删除，会话撤销，书架/书架事实/活跃日/点赞清空，内容隐藏软删除；审计保留。

### AT-P0-15 生产安全配置

- 步骤：分别使用完整配置、`CORS_ORIGIN=*`、HTTP 来源、开发微信身份、短后台密码、短监控令牌和小程序占位信息执行 `release:check`。
- 预期：只有完整配置通过；请求体超过 1 MB 为 413；高频请求为 429；通用 500 不回显内部错误；`/metrics` 使用独立 Bearer 令牌。
- 日志：以真实 Pino 输出写入带 AppSecret、后台/数据库密码、微信 code、Cookie、Bearer 和会话令牌的测试对象，逐值确认原文均不存在且被 `[REDACTED]` 替代。

### AT-P0-16～18 外部发布与灾备

- 小程序：真实 AppID、合法 HTTPS 域名、隐私声明配置完成后，在微信开发者工具和至少一台 iOS、Android 真机验证平台隐私指引可打开、待授权时出现同步控件、拒绝不登录、同意后继续业务协议校验，并执行全主链路。
- 部署：联网环境构建两个携带不同 OCI 源码提交的镜像，Caddy 自动签发证书，容器 `/ready` 健康；运行 `release:drill:production`，验证候选、上一版、候选恢复三个阶段的公网 HTTPS、核心接口、后台和监控，回执绑定当前提交、域名、镜像 ID 与近期备份。
- 异常：私网/保留 DNS、TLS 校验关闭、证书不可信或不足 7 天、HTTP 跳转错误、备份超过 26 小时或 SHA-256 不符、镜像/提交相同、任一阶段探测失败均必须拒绝；失败后候选镜像应自动恢复，恢复失败必须明确告警。
- 灾备：上线前生成 custom-format 备份，在隔离空库执行 `pg_restore`，再运行 `check:db` 与 `check:db-api`。
- 判定：任一项未实际执行均记为 `BLOCKED`，不得按假设标记通过。

### AT-P0-19 核心产品指标

- 步骤：使用两个匿名访客标识访问档案列表、人物详情、作品详情和同一作品正版链接；创建新用户并加入书架、完成作品、切换状态或移出书架后发布评价；构造第 7/30 日活跃、评论举报和首次审核记录；以后台角色查询 30～365 天统计。
- 预期：服务端只保存访客标识 SHA-256 摘要，不保存原始标识、IP 或设备信息；点击必须匹配同一访客此前访问的同一作品；首加书架分母只纳入已观察满 7 天的新用户，首次书架/完成事实不因状态切换或移出书架丢失；全部指标同时返回比例与分子/分母，零样本不产生除零或空值误导。
- 权限：游客和普通用户不能读取后台聚合；EDITOR、MODERATOR、ADMIN 只能读取汇总数据，不返回用户身份或正文。

### AT-P0-20 内容申诉与恢复

- 步骤：管理员隐藏已发布评价；非作者和作者分别提交申诉；作者重复提交；后台读取申诉队列并批准恢复；另建申诉后编辑/删除原内容。
- 预期：非作者 404；作者首次 201、开放申诉重复 409；批准、内容恢复、`moderation_records` 和 `audit_logs` 同事务完成；作者编辑/删除或注销时开放申诉转为 `CANCELLED`；后台显示申诉恢复率及样本量。

### AT-P1-09 社区动态发现

- 步骤：发布一条带剧透短评和一条长评；分别查询全部、短评和长评动态；按每页 1 条继续加载；打开作品和讨论详情；隐藏评价、下架作品、停用作者后重新查询；恢复作品后再查。
- API：`GET /api/v1/community/reviews?page=1&pageSize=20&reviewType=SHORT|LONG`。
- 预期：只返回 `PUBLISHED` 评价、`PUBLISHED` 作品和有效作者；类型筛选准确、排序按发布时间稳定、单页不超过 50；非法类型和 `pageSize=51` 为 400；作品下架时动态和评价详情同时不可见，恢复后重新可见；作者停用时分页总数同步减少。
- UI：社区作为独立 Tab；具有加载、有数据、空态、错误重试和加载更多状态；卡片显示作者、作品、类型、日期、评分和互动数，剧透正文必须主动展开后才显示。

### AT-P1-10 运营演练证据门禁

- 步骤：以实际清单负责人准备仓库外 JSON，分别记录内容审核、举报结案、用户限制和紧急下架四个场景；运行 `npm run operations:drill:record`，再执行 `launch:audit --phase=submission`。
- 正常：四个场景均为 `PASSED` 且有独立证据引用；负责人和实际上线清单一致；工具生成仓库外源记录不复制、`.release-state` 回执及清单摘要原子更新，`operations_drill` 为 `READY`。
- 异常：记录使用相对路径或位于仓库内、源码存在生产配置生成器之外的未提交变更、占位负责人、负责人错配、缺少/重复/失败场景、超出 5 分钟容差的未来时间、超过 90 天、运行手册摘要变化或手工仅勾状态时均必须拒绝，不覆盖已有清单。

### AT-P1-11 微信候选验收证据门禁

- 正常：真实候选上传回执与当前 AppID/提交一致；平台配置 4 项、内容安全 4 路径、iOS/Android 各 9 个场景全部为 `PASSED`，设备/系统/微信版本和非敏感证据引用完整；记录器原子写入回执后七个上线门禁同时为 `READY`。
- 异常：记录位于仓库内或使用相对路径、候选版本/AppID/提交/配置摘要/生产域名错配、缺少或重复平台/安全/设备场景、缺一端设备、设备运行超过 7 天、回执超过 30 天、证据引用含令牌/签名/URL 凭证或只恢复旧布尔字段时必须拒绝。

### AT-P1-12 微信发布生命周期证据门禁

- 正常：命名发布负责人依次记录 `REVIEW_SUBMITTED`、`REVIEW_APPROVED`、`PRODUCTION_RELEASED`；每步生成不可变回执并原子更新清单；相同证据重放幂等；三个上线门禁随阶段逐步就绪。
- 异常：首个事件不是提审、跳过审核、改写已记录事件、时间早于验收/前一事件、负责人/AppID/版本错配、候选或验收摘要变化、手册变化、记录位于仓库内、出现额外字段或证据引用含令牌/签名/URL 凭证时必须拒绝。
- 隐私：回执不得包含 AppSecret、微信 code、OpenID、用户数据、测试正文、风险文本原文或带签名下载地址。
- 安全：记录和回执不得包含密码、令牌、用户个人信息、违规正文或带签名下载地址；审计输出只显示状态、阶段、责任域和通用说明。

## 4. 数据一致性专项

| 链路 | UI | API | DB | 日志/审计 | 风险 |
|---|---|---|---|---|---|
| 书架 | 状态徽标、进度 | 最新 shelf item | 唯一组合、完成时间 | 普通访问日志不含正文/令牌 | 并发 upsert 最终态 |
| 评价 | 我的评价显示待审 | 作者可见、游客隐藏 | `status`、`deleted_at` | 创建/编辑/删除审计 | 编辑后旧内容短暂外泄 |
| 点赞 | 数量与本人状态 | `likedByMe`、`likeCount` | 组合唯一 | 请求路由指标 | 双击重复计数 |
| 举报 | 成功/重复提示 | 201/409 | 开放举报唯一 | 创建和结案审计 | 并发重复结案 |
| 申诉 | 我的评价显示状态和入口 | 201/409、后台批准/驳回 | 开放申诉唯一、批准与恢复同事务 | 创建、处置和恢复审计 | 重复恢复或原内容已变化 |
| 社区动态 | 类型筛选、剧透遮罩、加载更多 | 公开筛选与稳定分页 | 评价/作品/作者三重公开状态 | 普通读取不记录正文 | 下架内容残留、总数与结果不一致 |
| 运营演练 | 四场景清单与负责人 | 提审审计状态 | 非敏感回执写入忽略清单 | 场景证据引用、提交与手册摘要 | 伪造勾选、旧手册或过期培训 |
| 产品指标 | 后台比例与样本量 | 聚合且按角色保护 | 匿名摘要、自然日活跃、业务事实表 | 统计写入失败不阻断公开浏览 | 小样本误读、原始标识泄露 |
| 作品发布 | 后台状态徽标 | 管理/公开接口一致 | `status`、`published_at` | 发布者、请求 ID | 编辑越权直接发布 |
| 数据导出/注销 | JSON 文件；注销后返回未登录态 | 导出 200、超限 429；注销 204 后令牌 401 | 导出快照与本人数据一致；注销后身份删除、内容隐藏 | `DATA_EXPORT` 与注销审计保留 | 敏感内部字段泄露、部分事务导致残留 |

项目不使用业务缓存、消息队列或对象存储，因此本轮不虚构相关校验；部署后若引入，需补充失效与重试用例。

## 5. 用户体验评估

- 主路径：首页 → 档案室 → 侦探 → 作品应在 4 次页面跳转内完成；作品页可直接加入书架或写评价。
- 每个异步页面必须有加载、空态和错误态；错误态提供重试或返回入口，不允许按钮永久 loading。
- 自动模拟请求超时、断网、403、404 和八个异步页面首次读取失败，再切换为成功响应并执行页面重试入口；失败不能伪装成空列表，重试后错误状态必须清空。
- 登录前明确展示协议勾选；写评价、书架、点赞和回复遇到未登录时引导到“我的”。
- 剧透遮罩必须覆盖正文，不能在摘要、无障碍名称或错误信息中提前泄露。
- 导出前提示文件包含个人信息，由用户主动保存/分享；注销采用两次确认并清楚说明不可恢复影响。
- 后台空队列必须明确显示“当前没有待审内容/举报/申诉”，操作完成后自动刷新状态。

## 6. 风险与潜在缺陷预测

- EDITOR 与 ADMIN 的作品发布权限若未分离，会绕过内容复核，是发布阻塞风险。
- 同一举报并发结案可能产生误导性的 404 或重复审计，应使用条件更新并返回冲突语义。
- 内存限流只适用于单实例；扩容前需迁移到共享限流存储。
- 微信登录自动化替身不能验证真实 `code2Session`、合法域名和隐私弹窗。
- 小程序上传工具自动化可以验证输入、环境隔离、失败关闭和回执格式，但没有真实上传私钥时不能把候选上传判定为通过。
- 外部正版链接可能因地区、反爬或改版失效，需保留人工复核而非自动替换。
- 当前已有 143 部作品；生产流量下的慢查询和连接池参数仍需通过真实指标调整。
