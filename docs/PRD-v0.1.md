# 侦探档案馆 MVP 产品需求文档

| 项目 | 内容 |
|---|---|
| 文档版本 | v0.1 |
| 产品阶段 | 立项与基础工程 |
| 首发平台 | 微信小程序 |
| 产品定位 | 独立原创推理文化社区 |
| 首版重点 | 图鉴、正版链接、阅读记录、评论社区、运营后台 |
| AI 创作 | 第二阶段 |

## 1. 文档概述

本文定义“侦探档案馆”首个可发布版本的目标、边界、页面、业务规则、接口、数据模型、审核和验收方向。产品灵感来自经典侦探作品推荐形式，但不宣称与《名侦探柯南》或其权利方存在官方关系。

当前仓库已经建立可运行的档案浏览基础链路，但尚未形成完整 MVP。实际能力以第 14 节为准。

## 2. 产品背景与目标

### 2.1 用户问题

- 推理作品分散在书籍、影视和不同平台，缺少以“侦探人物”为入口的统一索引。
- 用户读完或看完后，难以找到围绕同一人物和作品的持续讨论空间。
- 普通推荐列表通常缺少阅读进度、剧透管理和正版获取渠道。
- AI 创作工具与推理兴趣社区割裂，生成内容缺少作品沉淀和反馈场景。

### 2.2 产品目标

1. 帮助用户从一位侦探持续发现相关的书籍和影视作品。
2. 通过正版链接缩短“发现—阅读/观看”的路径。
3. 让用户记录阅读/观看状态，并围绕作品发布短评或长评。
4. 建立具有剧透保护、举报和审核能力的友好推理社区。
5. 第二阶段支持原创侦探故事与视频创作，不复刻受保护角色和剧情。

### 2.3 关键指标

首版记录以下指标，具体目标值需在获得首批真实流量后确认：

- 档案详情访问率。
- 作品详情到正版渠道的点击率。
- 新用户首次加入书架的转化率。
- 完成阅读/观看后发布评价的比例。
- 7 日与 30 日留存。
- 评论举报率、审核处理时长和申诉恢复率。

### 2.4 首版非目标

- 不提供盗版阅读、下载或视频播放。
- 不建设私信、群聊和复杂小组体系。
- 不实现付费订阅、电商结算或广告系统。
- 不在首版提供 AI 视频生成。
- 不使用未经授权的柯南角色、插图、原文或官方品牌元素。

## 3. 用户角色与权限

| 角色 | 核心权限 |
|---|---|
| 游客 | 浏览已发布档案、作品、公开评论；访问正版链接 |
| 注册用户 | 管理个人书架；发布、编辑和删除自己的评价；回复、点赞、举报 |
| 内容编辑 | 维护侦探、创作者、作品和正版链接；提交发布审核 |
| 审核员 | 审核用户内容、处理举报、隐藏或恢复内容、警告用户 |
| 管理员 | 分配角色、管理账号状态、查看审计日志与系统配置 |

规则：

- 所有写操作必须登录。
- 用户只能修改自己的书架和未被锁定的自有内容。
- 编辑不能自行提升权限或删除审计记录。
- 审核员的每次处置必须填写原因并写入审计记录。
- 管理员权限变更不得由客户端字段决定。

## 4. 核心业务流程

### 4.1 发现与消费作品

```text
首页/搜索 → 侦探档案 → 代表作品 → 作品详情
→ 选择正版渠道 → 外部阅读/观看 → 返回记录进度
```

异常规则：链接无效时停止跳转并允许用户反馈；下架作品不出现在公开搜索中，但用户历史记录仍保留占位说明。

### 4.2 阅读记录与评价

```text
作品详情 → 加入书架 → 想读/在读/已读
→ 评分 → 短评或长评 → 内容安全检查 → 发布/待人工审核
→ 回复、点赞、举报
```

规则：同一用户对同一作品只保留一条书架记录。短评和长评均可标记剧透；剧透正文默认折叠。

### 4.3 内容运营

```text
编辑新建草稿 → 补充来源 → 关联人物/作品/正版链接
→ 提交审核 → 审核通过 → 发布 → 定期检查链接 → 更新或下架
```

### 4.4 AI 原创视频（第二阶段）

```text
原创设定 → 安全预检 → 生成剧本/分镜 → 创建视频任务
→ 生成成功/失败 → 用户预览 → 发布审核 → 社区展示
```

AI 任务失败可重试，但每次重试需要独立记录费用和模型信息，禁止不受控自动重试。

## 6. 功能需求明细

### 6.1 侦探档案

**目标**：用人物作为内容入口，帮助用户发现代表作品。

**输入**：关键词、国家、流派、年代、分页条件。
**输出**：人物名称、原名、国家、创作者、简介、标签和代表作品。

核心规则：

- 公开接口只返回 `PUBLISHED` 档案。
- 人物 `slug` 全局唯一，发布后修改需保留重定向关系。
- 简介必须为原创编辑内容或具有明确授权，来源备注仅后台可见。
- 搜索匹配中文名、原名、作者和标签；单次最多返回 50 条。

边界情况：空搜索返回默认排序；无结果显示空状态；失效 ID 返回稳定的 404 错误。

当前证据：人物列表和详情接口已在 `apps/api/src/routes/detectives.ts` 实现；第 1～108 卷图鉴索引、搜索、卷号筛选和详情接口已在 `apps/api/src/routes/picture-book.ts` 实现。小程序首页、图鉴索引和详情页位于 `apps/miniprogram/pages`。完整图鉴索引来自 `apps/api/src/data/picture-book-index.json`，人物详细资料目前仍只有三条演示数据，数据库接入尚未完成。

### 6.2 作品与正版链接

**目标**：说明作品信息，并让用户明确前往正规渠道。

核心规则：

- 作品支持小说、短篇、漫画、电影、剧集、动画、游戏等类型。
- 同一作品可关联多位侦探与多位创作者。
- 链接必须显示渠道名称、类型和适用地区。
- 链接按人工维护状态和最近检查时间决定是否展示。
- 外部渠道价格、库存和可播放状态不在本产品内做持续承诺。

当前证据：关系和状态已在 `database/schema.sql` 设计；作品详情和链接接口未实现。

### 6.3 微信登录

**目标**：建立稳定用户身份并支持跨设备书架。

核心规则：

- 客户端获取一次性登录凭证，服务端与微信交换身份，不向客户端暴露 AppSecret。
- 首次登录创建用户和身份映射；重复登录返回同一用户。
- 令牌应短期有效并支持服务端失效。
- 被停用用户不能执行写操作，但可按政策申请数据导出或注销。

当前状态：未实现；数据表 `users`、`user_identities` 已设计。

### 6.4 我的档案馆

**目标**：记录用户想读、在读、已读或对应观看进度。

核心规则：

- 同一用户与作品组合唯一。
- 更新接口采用 upsert，重复请求保持幂等。
- 完成状态自动将进度设为 100%，记录完成时间。
- 从完成状态退回其他状态时保留历史事件；首版可暂只保存当前状态，事件历史列为后续增强。

当前状态：数据表 `shelf_items` 已设计，接口和页面未实现。

### 6.5 短评、长评与评分

**目标**：让用户在作品语境内留下可沉淀的阅读或观看感受。

核心规则：

- 评分为 1～5 分，可不评分只写正文。
- 长评必须有标题；短评不要求标题。
- 正文发布前执行长度、敏感内容和频率校验。
- 用户主动标记剧透；审核员也可补充剧透标记。
- 已发布内容编辑后重新执行安全检查。
- 删除采用软删除；其他用户不再看到正文。

当前状态：`reviews` 数据表和约束已设计，业务未实现。

### 6.6 回复、点赞和举报

**目标**：支持围绕评价的有限互动，并形成治理闭环。

核心规则：

- 回复层级首版展示两层，数据库保留父评论引用。
- 同一用户对同一内容只能点赞一次。
- 举报需选择原因，可补充说明；举报人不能看到审核员内部备注。
- 重复举报不得重复增加处罚权重，系统应合并展示给审核员。

当前状态：数据表已设计，页面与接口未实现。

### 6.7 运营后台

**目标**：保证内容可以持续维护、审核和追溯。

核心规则：

- 内容草稿与发布权限分离；至少保留发布人和发布时间。
- 批量导入必须先预检，错误数据不能部分静默丢失。
- 外链定期检测，仅自动标记异常，不自动替换为未知渠道。
- 审核、封禁和恢复操作必须写审计日志。

当前状态：数据结构已设计，后台应用未实现。

### 6.8 AI 原创创作

**目标**：在第二阶段帮助用户把原创推理设定制作成短视频。

核心规则：

- 默认只允许原创人物与剧情。
- 创建任务前提示预计费用并由用户确认。
- 生成任务异步执行，失败原因可见且可控重试。
- 发布前执行机器与人工审核，并标注 AI 生成。
- 保存模型、任务状态、费用和结果地址，支持追溯。

当前状态：仅 `ai_creation_tasks` 数据表预留，未接入模型或媒体服务。

## 9. 核心数据模型

| 实体 | 作用 | 关键约束 |
|---|---|---|
| users / user_identities | 用户与微信身份映射 | 外部身份唯一 |
| detectives | 侦探档案 | slug 唯一、发布状态 |
| creators | 作者、导演等创作者 | 可关联人物与作品 |
| works | 书籍与影视作品 | 类型、年代、发布状态 |

| work_links | 正版渠道链接 | 渠道、地区、有效状态 |
| shelf_items | 用户阅读/观看进度 | 用户+作品唯一 |
| reviews / comments | 评价与回复 | 审核、剧透、软删除 |

字段和约束详见 `database/schema.sql`。

## 10. 状态流转与异常处理

### 10.1 内容状态

```text
DRAFT → PENDING_REVIEW → PUBLISHED
                     ↘ HIDDEN → PUBLISHED
PUBLISHED → ARCHIVED
```

普通用户只能访问 `PUBLISHED` 内容。隐藏与归档不得删除书架、评价和审计关联。

### 10.2 阅读/观看状态

```text
WISHLIST → IN_PROGRESS → COMPLETED
              ├→ PAUSED
              └→ DROPPED
```

用户可以修改状态；完成状态必须同步进度和完成时间。

### 10.3 举报状态

```text
OPEN → PROCESSING → RESOLVED
                  ↘ REJECTED
```

处置失败不能丢失原举报；并发处理使用版本号或数据库条件更新避免重复结案。

### 10.4 AI 任务状态

```text
DRAFT → QUEUED → GENERATING → SUCCEEDED → PENDING_REVIEW → PUBLISHED
                         └→ FAILED                        └→ REJECTED
```

### 10.5 通用异常

- 参数错误：400，返回稳定业务错误码。
- 未登录：401；无权限：403。
- 资源不存在或不可见：404，避免泄露隐藏内容。
- 版本冲突或重复操作：409。
- 频率受限：429，并提供可重试时间。
- 外部服务失败：记录依赖、耗时和请求 ID；不在日志中记录密钥。

## 11. 日志、审计与追溯

- 每个请求生成或接收 `x-request-id`。
- 登录、内容发布、链接变更、审核、封禁和角色变更写结构化日志。
- 人工处置写入 `moderation_records`，系统关键变更写入 `audit_logs`。
- 用户正文不应完整写入普通访问日志。
- AI 任务保留模型名称、提示词摘要、费用、失败码和审核记录。
- 审计日志只允许追加，普通后台用户不得编辑或删除。

## 12. 非功能需求

### 性能

- 列表接口必须分页，单页不超过 50 条。
- 高频公开详情可使用短期缓存，内容发布或下架时主动失效。
- 图片采用缩略图和懒加载；视频走对象存储与 CDN。

### 稳定性

- API 提供健康检查。
- 数据库启用自动备份；发布前演练恢复流程。
- 外部链接、审核和 AI 服务故障不应阻断基本档案浏览。

### 安全与隐私

- 全链路 HTTPS。
- 密钥通过环境变量或密钥服务管理。
- 写接口进行身份、权限、归属、输入长度和频率校验。
- 收集用户信息遵循最小必要原则，并提供注销与数据处理入口。

### 扩展性

- 人物、作品和创作者采用多对多关系。
- 社区与 AI 模块不进入公开档案查询的关键依赖链。
- API 使用版本前缀，避免客户端升级时破坏兼容性。

## 18. 一页式版本摘要

**产品**：侦探档案馆，一个通过名侦探人物连接经典书籍、影视作品、阅读记录和同好讨论的微信小程序。
**用户价值**：更容易找到下一部值得读或看的推理作品，并把阅读经历沉淀为个人档案与社区讨论。
**首版闭环**：发现人物 → 查看作品 → 跳转正版渠道 → 记录进度 → 写评价 → 参与讨论。
**当前进度**：已完成基础小程序、覆盖第 1～108 卷的 109 条图鉴索引、扩展目录、PostgreSQL 仓储、增量迁移、5 部作品详情与首批官方链接；人物深度资料、用户、社区和后台尚未闭环。
**首版边界**：不提供盗版内容，不做私信群聊，不做支付，不把 AI 视频作为上线阻塞项。
**下一里程碑**：完成首批 30 位人物和代表案件核验，并实现数据库、作品详情、微信登录、书架、评论审核与运营后台后进入完整验收。
