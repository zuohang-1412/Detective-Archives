## 字段核验状态

- `MISSING`：来源未提供，保持为空。
- `SOURCE_CAPTURED`：已从单个社区索引或 Wiki 提取，仍需第二来源核对。
- `PRIMARY_SOURCE_CONFIRMED`：已经出版社或其他一手来源确认。

人物身份和推荐作品分别记录核验状态，不因为人物名称已确认就默认推荐作品也正确。

## 内容合规边界

仓库只保存卷号、名称、别名、推荐作品名、发布日期和来源等事实字段：

- 不保存或分发图鉴图片。
- 不复制帖子或漫画中的人物长介绍。
- 后续人物简介与案件简介重新原创撰写。
- 原作案件详情区分无剧透摘要与剧透梗概。
- 正式发布前，中文译名、人物创作者、推荐作品和正版链接至少完成一次交叉核验。

## 数据生成与检查

`scripts/sync-picture-book-index.mjs` 从 Bilibili 页面提取第 1～100 卷事实字段，并合并第 101～108 卷补充索引。脚本对 1～100 卷执行连续性检查，缺卷时拒绝覆盖输出。

`scripts/check-catalog.mjs` 进行离线完整性检查，包括：

- 108 个标准卷是否连续且唯一。
- 第 105 卷特装版是否独立编号。
- 编号、来源、HTTPS 地址和核验状态是否合法。
- 是否意外保存了来源简介或图片字段。
- 推荐作品条目数量是否与数据快照一致。

## 档案馆扩展收录

扩展目录与卷号图鉴使用独立编号，不改变或续接 `PB-` 编号：

- `EXT-WL-*`：世界文学侦探。
- `EXT-SC-*`：影视侦探。
- `EXT-JP-*`：日本小说、漫画和影视侦探。
- `EXT-CN-*`：华语侦探文学人物。
- `HIS-CN-*`：中国历史断案人物。

当前收录 32 位图鉴外虚构侦探与 3 位历史人物。新增全球文学人物使用官方创作者或出版社的系列页和首部作品页双重确认人物、系列与代表作；历史人物页面必须明确区分史实、后世公案文学与影视改编，不把文学案件表述为真实经历。

扩展条目优先使用出版社、创作者官网、正版平台、公共机构或图书馆目录。每条记录保存名称、别名、地域、创作者、媒介、代表作品、原创短简介、标签、来源和核验状态，不保存书封、剧照或来源长文。

扩展目录执行独立完整性检查：

```bash
npm run check:directory
```

检查内容包括稳定编号、数量、来源、HTTPS 地址、必填字段、史实/虚构分组，以及与现有图鉴中文主名称的重复检测。

`apps/api/src/data/catalog-expansion-china-001.json` 是第 23 个不可变批次。它使用中国作家网关于孙了红/鲁平的文学专题、对雷米的作者专访，以及衢州市图书馆、WorldCat 馆藏书目，为鲁平和方木补齐第二层权威来源与各一部正式作品。两条人物记录均从 `SOURCE_CAPTURED` 升级为 `PRIMARY_SOURCE_CONFIRMED`；数据库完整性门禁随后要求所有已发布人物的单源记录数量必须为零。

`apps/api/src/data/catalog-expansion-manifest.json` 维护不可变批次的执行顺序。每轮先执行 `npm run catalog:preflight`，逐批检查编号、slug、来源引用、图鉴编号和数据库冲突；确认无错误后执行 `npm run catalog:apply`。数据库保存批次键、原文件 SHA-256 校验和、变更摘要和应用时间，同一批次内容一旦应用后不得原地修改，后续扩充必须创建新文件与新批次键。

错误批次采用前向补偿，不删除可能已有书架、评价或审计引用的记录。补偿文件必须位于清单末尾，以 `rollbackOf` 指向紧邻的最新批次、填写不少于 10 字的 `rollbackReason`，并恢复旧档案、通过 `archiveDetectiveSlugs` / `archiveWorkSlugs` 归档新内容，或用 `pictureBookRecommendationUnmappings` 解除错误推荐映射。先执行 `npm run catalog:rollback:preflight -- --file=...`，确认差异后再执行 `npm run catalog:rollback:apply -- --file=...`。成功后原批次标记为 `ROLLED_BACK`，补偿批次标记为 `APPLIED`，重复执行保持幂等；归档作品的公开链接会同步停用，原始图鉴推荐标签始终保留。

正版链接通过 `npm run links:check` 定时巡检。巡检区分健康、确认失效和暂无法确认三种结果：只有 GET 明确返回 400、404 或 410 才累计确认失败；超时、TLS、DNS、反爬、429、451、5xx 或抓取失败保存底层错误码并进入人工复核。自动结果不会直接下架；管理员须在后台填写不含令牌/签名的证据引用，确认有效结论 90 天内关闭不确定/超期队列，确认失效则在同一事务停用链接并记录审计。后续自动确认失效不会被旧人工结论遮蔽。
