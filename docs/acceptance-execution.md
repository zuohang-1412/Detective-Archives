## 2. P0 执行步骤

### 公开浏览主链

1. `GET /ready` 必须为 200 且 `database=connected`。
2. `GET /api/v1/detectives?pageSize=50` 校验 `pagination.total=132`。
3. 搜索“波洛”、访问 `sherlock-holmes`、校验 120 部作品、图鉴 109 条和扩展目录 23 条。
4. 进入作品详情，校验侦探、创作者、简介、正版链接；停用链接后公开结果立即移除，原页面再次复制返回 404、停止操作并提示提交链接反馈，不回退缓存旧地址。
5. 对照 `detectives`、`works`、`work_links`、图鉴表和来源关系，禁止孤儿数据。

### 身份与书架主链

1. `POST /auth/wechat` 缺少两个同意字段应为 400。
2. 携带两个 `true` 后并发登录三次，所有响应 user ID 相同。
3. `PUT /me/shelf/:workId` 并发五次，记录 ID 唯一；改为 `COMPLETED` 后进度为 100。
4. 第二用户查询该作品返回 `data=null`。
5. 退出后 `GET /auth/me` 使用旧令牌返回 401。

### 社区与治理主链

1. 用户 A 创建带剧透短评，响应 `PENDING_REVIEW`；游客列表总数不增加。
2. 管理员发布后游客可见；用户 B 并发点赞五次，`likeCount` 始终为 1。
3. 用户 B 回复，管理员发布；用户 A 并发举报两次，结果必须为 201 和 409。
4. 两个并发结案请求只能有一个成功；审计表只产生一次最终结案动作。
5. 作者编辑后评价回待审并从公开详情消失；他人删除为 404，作者删除为 204。

### 目录发布权限主链

1. EDITOR 创建作品，初始状态为 `DRAFT`。
2. EDITOR 直接请求 `PUBLISHED` 必须 403；创建链接时 `isActive=false`；启用链接必须 403。
3. EDITOR 提交 `PENDING_REVIEW`；ADMIN 才能发布。
4. 发布后 EDITOR 修改应为 409 `WORK_NOT_EDITABLE`；ADMIN 可隐藏或恢复。
5. 后台浏览器应依次显示“提交审核”“发布”“隐藏”“恢复发布”。

### 注销与生产门禁

1. 注销缺 `confirmation=DELETE` 为 400；确认后 204。
2. DB 校验身份 0、会话撤销、用户 `is_active=false`、展示名去标识化、内容隐藏、审计保留。
3. `ops/deploy-release.sh` 只在 HTTPS CORS、微信/后台/监控凭证和真实小程序配置齐全时继续，并强制执行匹配版本备份、数据库完整性与 HTTP/监控探测。
4. GitHub 候选环境构建两个不同镜像，部署候选后核对 `current-image-tag`/`previous-image-tag` 与实际容器，再执行默认上一镜像回滚并重复数据库、HTTP、监控探测。
5. P0-18 已在隔离恢复库完成；P0-16～17 的外部部分仍必须在真实微信、正式域名和正式服务器执行，不能由候选演练替代。

## 3. 标准化校验点

- UI：标题/按钮/状态徽标、加载、空态、错误、禁用与完成反馈均可见；不读取隐藏正文。
- API：状态码、业务错误码、字段、分页、请求 ID、无缓存头和权限边界精确匹配。
- DB：唯一约束、状态、时间字段、软删除、身份/会话、关联数量与公开结果一致。
- 日志/审计：关键动作包含 actor、resource、request ID、原因/元数据；不含密钥、密码、code 和完整 token。
- 缓存/消息：当前版本无业务缓存和消息队列，标记为“不适用”，不得虚构通过。

## 4. 异常与执行顺序

- 异常：无令牌、错误角色、错误 UUID、空正文、长评无标题、进度越界、重复评价/举报、超大正文、高频登录和 DB 断连。
- 并发：同身份登录、同作品书架、同内容点赞/举报、同举报结案。
- 顺序：先 P0 软件主链，再 P1 权限/并发/数据，最后 P2 监控/体验/性能。

## 5. 测试通过标准

- 所有可执行 P0、P1 必须通过，S0/S1 缺陷必须关闭。
- 真机和 HTTPS 正式部署两个外部 P0 未执行时，不得判定“可正式上线”。
- 候选容器性能门禁已通过；上线后必须继续采集公网 P95、错误率、连接池和限流指标。
- 当前结论：软件版本和灾备恢复可进入发布候选；由于正式微信真机、HTTPS 服务器/回滚和法务主体配置未满足，暂不可全量发布。
