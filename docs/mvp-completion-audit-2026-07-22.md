更新日期：2026-07-22
审计基线：`docs/PRD-v0.1.md`、当前 `codex/mvp-release` 代码、真实 `detective_archives` PostgreSQL 与自动化验收结果。

## 1. 审计结论

PRD 6.1～6.7 的 MVP 软件范围已经形成可部署闭环；逐条反查先后关闭了剧透纠正、作品运营端多创作者/多侦探编辑，以及 13 位目录人物缺少可发现代表作品三个缺口。批量导入器现与运营端一致支持显式创作者身份。6.8 AI 原创创作按 PRD 明确属于第二阶段，不作为首次上线阻塞项。

当前状态是“软件发布候选完成，等待外部上线条件”，不等同于已在微信正式发布。真实 AppID/AppSecret、公众平台配置、生产域名和服务器、TLS、真实监控/离站恢复回执、运营主体与法务信息、真机验收和微信审核必须由相应账号或资源持有人提供。

## 4. 本次缺口关闭说明

原实现允许用户自行标记剧透，但运营人员只能发布、拒绝、隐藏或恢复内容，无法在不改变内容状态的情况下纠正剧透属性。现已新增：

1. 评价和回复的补标/取消剧透动作，仅 `MODERATOR` 与 `ADMIN` 可调用。
2. 待审、已发布和已隐藏内容均可纠正，删除或拒绝内容不可操作。
3. 目标行加锁，重复设置相同值返回幂等结果，不重复写处置记录。
4. 实际变化同时写入 `moderation_records` 与 `audit_logs`，保留原因、前后值、操作者和请求 ID。
5. 待审队列与举报队列都提供操作入口，公开 API 立即反映新标记但内容审核状态不变。

第二次审计发现作品运营端未暴露数据库已有的多对多能力，现已新增：

1. 创作者按姓名和作者/编剧/导演/绘者/编辑/其他身份成组维护，同一作品最多 20 项。
2. 运营人员可搜索并勾选最多 20 位侦探，创建和编辑时完整回填。
3. 作品字段、创作者和侦探关系在同一事务内完整替换；不存在侦探会返回稳定 404 并回滚全部变化。
4. 重复创作者身份或重复侦探在 API 写库前拒绝，数据库组合主键继续提供最终保护。
5. 后台列表可按关联创作者/侦探搜索，公开作品详情和侦探详情同步使用新关系；审计日志记录关联数量。

第三次审计以“人物必须能带用户发现作品”为口径复查真实数据库，发现霍桑、罗飞、L、金田一一、加贺恭一郎、姬川玲子、贝努瓦·布兰克、杰西卡·弗莱彻、维罗妮卡·玛斯、戴尔·库珀、狄仁杰、包拯和宋慈共 13 位已发布人物尚无正式作品关系。现已完成：

1. 为 13 位人物补入来源核验的代表作品，以及出版社、制片方、流媒体、图书目录或公共机构入口。
2. 导入器新增多创作者及作者/编剧/导演/绘者/编辑/其他身份校验，更新作品时事务化完整替换创作者关系。
3. 静态与数据库完整性门禁新增“每位目录人物至少一部正式作品”和“每部正式作品必须有创作者、人物及有效入口”约束。
4. Hulu 的确认 404 通过不可变补偿批次替换；Apple TV 因对生产巡检客户端固定返回 404 被进一步回滚，最终使用健康的 Prime Video 官方入口，并保留两层历史审计。
5. 当前形成 160 部公开作品、161 条有效入口；全量在线巡检为 103 条健康、0 条确认失效、58 条暂无法自动确认。
