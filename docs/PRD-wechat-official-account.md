# 侦探档案馆微信公众号 PRD

状态：当前有效

产品形态：纯微信公众号

版本：1.0

## 1. 产品目标

“侦探档案馆”通过微信公众号持续发布不剧透、可追溯、可收藏的侦探人物与案件内容，帮助读者找到经典推理作品及合规阅读入口，并通过留言、投票和原创谜题形成轻量互动。

## 2. 当前范围

- 开馆说明与编辑原则；
- 人物总档案、正典范围和案件时间线；
- 沿人物经历排列的单案无剧透导读；
- 入门书单、主题书单和扩展人物档案；
- 公众号投票、留言问题和原创谜题；
- 原创或明确授权的图片、信息图和 AI 辅助视觉；
- Markdown 源稿、资料来源、生成记录和 DOCX 导入版。

## 3. 不在当前范围

- 微信小程序及其审核发布；
- 独立网站、H5、API 和线上数据库；
- 微信登录、用户账号、个人书架、评分、回复和社区；
- 自建运营后台、运行监控和数据库备份任务；
- 自动发布到公众号后台。

历史实现继续保留在仓库中供未来参考，但不进入当前发布链路。

## 4. 内容单元

每篇稿件至少包含：

- 唯一标题、栏目和编辑状态；
- 公众号摘要、封面短标题和预计阅读时间；
- 不泄露核心谜底的正文；
- 可复查的资料来源或合规阅读入口；
- 图片来源、授权、公共领域或生成记录；
- 版权与独立项目说明；
- 一条适合留言或投票的互动问题。

## 5. 发布流程

1. 选题进入排期并确定无剧透边界。
2. 使用权威来源完成事实卡和版本信息。
3. 在 `content/wechat/` 撰写 Markdown，制作并登记配图。
4. 执行 `npm run check`。
5. 执行 `npm run build:wechat` 生成 DOCX。
6. 在公众号后台导入并完成手机预览、封面、链接和版权复核。
7. 人工发布并更新稿件状态。
8. 发布 7 天后记录指标，决定后续选题与形式。

## 6. 数据策略

文章和公开资料全部进入 Git。公共目录由仓库中的 JSON 与不可变批次维护，不依赖数据库。用户身份、登录信息、令牌、评论导出和数据库归档不得进入 Git。

本地 PostgreSQL 及其 `.dump` 只作为历史系统恢复副本；纯公众号运营无需启动数据库容器。

## 7. 核心指标

- 读完率；
- 收藏率；
- 转发率；
- 在看率；
- 留言参与率；
- 单篇新增关注；
- 同一人物后续文章的回访比例。

首月优先判断“是否有人愿意读完、收藏和继续追更”，不以单篇总阅读量作为唯一结论。

## 8. 验收标准

- 默认检查无需数据库、Docker、微信 AppSecret 或生产域名即可通过；
- 已标记为可审稿或可发布的文章均有完整元数据、来源和版权说明；
- 本地图片引用全部存在且不能逃逸 `content/wechat/`；
- 数据库归档、环境文件和生成 DOCX 不被 Git 跟踪；
- 已接入生成器的文章能产生结构完整、包含图片替代文字的 DOCX；
- 发布前完成人工手机预览和版权复核。
