### DAA-001 复现证据

- 角色：数据库中角色为 `EDITOR` 的真实测试用户。
- 请求：`POST /api/v1/admin/works/:id/status`，正文 `{"status":"PUBLISHED"}`。
- 修复前响应：HTTP 200，`data.status=PUBLISHED`；同一用户访问审核队列为 403，说明角色本身识别正确，缺陷位于作品状态授权。
- 根因：状态路由将 `EDITOR` 和 `ADMIN` 放在同一允许列表；作品更新和链接启用也没有区分草稿维护与发布动作。

### 修复说明

- EDITOR：可创建/编辑 `DRAFT` 或 `PENDING_REVIEW`，只能提交 `PENDING_REVIEW`；新建链接默认停用。
- ADMIN：可将待审作品发布、隐藏、恢复或归档，并启停链接。
- 已发布作品：EDITOR 修改返回 409 `WORK_NOT_EDITABLE`。
- 状态机从后台“草稿直接发布”改为“草稿 → 待审 → 发布 → 隐藏/恢复”。
- 无数据库迁移和历史数据修复需求；现有已发布内容由管理员或初始化过程产生，状态合法。

### DAA-002 复现与修复

- 根因：`Dockerfile` 的生产启动命令依次执行迁移和基础目录种子后直接启动 API，遗漏 `run-catalog-imports.mjs --apply`；现有数据库因开发阶段已单独导入，所以常规回归没有暴露问题。
- 影响：缺陷发现时，全新部署或灾备重建会缺少 124 条目录扩展记录和 114 部批次作品；当前批次数量已继续增长，部署会按清单动态应用全部批次。
- 修复：在服务监听前按清单应用全部不可变批次，并新增 `check:deployment` 检查启动顺序、非 root 用户、只读文件系统、禁止提权、回环端口和就绪探针。
- 回归：全新 PostgreSQL 隔离库依次应用 001～008、基础种子和当前 19 个批次，结果精确为 132 位人物、120 部作品、109 条图鉴，随后真实 DB API 生命周期通过。

### DAA-003 复现与修复

- 复现：使用 PostgreSQL 17 `pg_dump` 备份 PostgreSQL 16.12 服务端，归档目录和校验和均正常，但恢复到同一主版本隔离库时因 `transaction_timeout` 参数不受支持而返回错误。
- 根因：原脚本只检查工具是否存在，没有核对客户端与服务端主版本；“能导出”不能证明归档可无错误恢复。
- 修复：备份前通过 `psql` 读取服务端版本并与 `pg_dump` 主版本精确比较；同时要求专用绝对目录、写入 SHA-256 边车文件，并提供默认关闭的私网每日备份任务。
- 回归：不匹配的 17 客户端在导出前被拒绝；匹配的 16 客户端重新生成当前归档，随后在隔离库完成 132/120/109 完整性及全 API 生命周期回归。

### DAA-004 复现与修复

- 复现：在独立空库启动基线镜像，迁移、基础种子和 19 个批次完成后图鉴关联为 109；切换候选镜像时再次运行基础种子，关联数降为 3，严格数据库门禁拒绝发布并自动恢复基线镜像。
- 根因：`picture_book_entries` 的基础 upsert 会用基础索引中的空 `detective_id` 覆盖扩展批次关联；基础目录重建还可能回退重叠人物的字段、来源和代表案件。批次已有成功记录，因此后续运行器按设计不重复应用旧批次。
- 修复：基础种子明确为“空库引导层”；检测到任一 `catalog_import_batches` 历史后不再改写基础目录，正式新增和纠错继续通过不可变批次追加。
- 回归：双镜像演练在第二次启动、候选验证和上一镜像恢复后三次核对 132/120/109，109 条图鉴均保留人物关联；部署前备份、状态文件、公开接口、后台和指标同时通过。

## 5. 统一分析

本轮关闭四个 S1 缺陷：作品发布权限越权、生产冷启动遗漏目录批次、备份客户端主版本不匹配，以及重复镜像启动覆盖扩展图鉴关联。四者分别通过多层权限约束、空库冷启动门禁、备份前版本拒绝与真实恢复演练、不可变批次优先的种子保护闭环。发布入口现已包含强制备份、带提交号镜像、数据库/HTTP 探测、失败自动恢复和显式回滚脚本；候选流水线进一步用两个不同镜像实际验证部署与恢复，相关回归未发现新的 S0/S1 问题。

剩余风险不是代码缺陷，但会直接阻止全量发布：真实微信 `code2Session`、平台隐私声明、备案 HTTPS 域名和生产部署回滚尚无外部证据。内存限流适合当前单实例；未来扩容需改为共享存储。外链巡检中的 41 条网络不确定项需由运营按批复核，但当前没有确认失效地址。

## 6. 最终结论

- 可继续提测：是。
- 可进入微信体验版和候选环境：是。
- 可产品验收：软件功能部分可以；外部发布验收尚未完成。
- 可正式上线：否。
- 上线前必须完成：AT-P0-16 真机、AT-P0-17 HTTPS 部署/回滚，以及真实运营主体/隐私文本确认。AT-P0-18 备份恢复已经通过。
