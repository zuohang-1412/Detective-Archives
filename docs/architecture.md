# 侦探档案馆技术架构 v0.1

## 1. 架构目标

首版优先支持“发现作品—查看详情—记录进度—发表评论—参与交流”的业务闭环，同时保持较低的启动和运维成本。AI 视频能力作为异步扩展服务接入，不进入首版关键路径。

## 2. 系统边界

```text
微信小程序
   │ HTTPS JSON API
   ▼
Fastify API ───────── 内容审核服务（后续）
   │                  对象存储/CDN（后续）
   │                  AI 任务服务（第二阶段）
   ▼
PostgreSQL
```

### 小程序端

- 技术：原生微信小程序。
- 职责：页面展示、交互状态、微信登录凭证获取、请求 API。
- 原则：不在客户端保存业务密钥；服务端返回前执行权限与内容状态校验。

选择原生方案是因为首发平台已经明确为微信小程序，能够减少跨端框架的编译和适配成本。若后续 H5 成为主要入口，再评估提取共享组件或迁移跨端框架。

### API 服务

- 技术：Node.js、TypeScript、Fastify、Zod。
- 职责：身份认证、内容查询、书架状态、评论互动、审核与后台接口。
- API 前缀：`/api/v1`。
- 错误结构：`{ code, message, details? }`。
- 当前实现：公开目录、微信身份、轮换会话、个人书架、社区互动、人工审核、内容运营、角色管理、审计检索、正版链接反馈和运行监控均已接入 PostgreSQL。

### 数据库

- 技术：PostgreSQL。
- 设计重点：规范化人物、作品与创作者关系；社区内容保留审核状态；所有关键操作可以审计。
- 当前状态：已经接入连接池和 `/ready` 就绪检查，具备不可变初始迁移、顺序增量迁移、幂等目录初始化、完整性检查和数据库 API 集成检查。API 在生产配置数据库时读取 PostgreSQL，未配置数据库的自动化测试保留仓库数据回退。

## 4. 身份与权限

建议角色：

- `USER`：浏览、收藏、评论、举报自己的正常用户行为。
- `EDITOR`：维护人物、作品和正版链接，但不能管理系统权限。
- `MODERATOR`：审核用户内容、处理举报和限制违规内容。
- `ADMIN`：账号、角色和系统配置管理。

服务端必须以数据库角色为准，不能信任客户端传入的角色或用户 ID。

## 5. 数据一致性

- 同一用户对同一作品只有一条书架记录，通过唯一约束保证幂等。
- 点赞使用组合唯一键，重复点击不能产生重复计数。
- 评论审核状态与公开查询隔离，普通用户只能看见 `PUBLISHED` 内容。
- 正版链接下架后保留历史记录，由状态字段控制展示，不物理删除审计证据。
- 内容状态变化、封禁和人工审核写入审计日志。

## 6. API 安全基线

- 所有写接口执行登录、角色、资源归属和输入校验。
- 单个请求体默认不超过 1 MB；图片和视频使用对象存储直传方案。
- 登录、评论、点赞、举报和 AI 创建接口实施频率限制。
- 密钥只来自部署环境，不提交到 Git。
- 日志记录请求 ID、操作者、资源与结果，不记录 AppSecret、登录凭证或完整令牌。
- 生产环境仅允许配置过的 HTTPS 来源，不使用通配 CORS。

## 7. 可观测性

首版已经通过受 Bearer 凭证保护的 `/metrics` 暴露请求总量、状态码、路由响应时间以及 Node.js 进程指标，可由 Prometheus 兼容平台采集。结合路由和状态码可计算登录、社区发布和后台操作的成功率。运维还应至少观察：

- API 请求数量、错误率和响应时间。
- 登录成功率。
- 作品详情到正版链接的点击转化。
- 评论发布、审核拒绝和举报数量。
- 数据导入失败与失效链接扫描结果。

## 8. AI 服务接入原则

AI 视频采用异步任务：创建任务 → 安全预检 → 排队生成 → 结果审核 → 发布。任务必须包含模型版本、提示词摘要、费用、失败原因和审核记录。原创人物为默认选项，受保护角色和作品内容不得直接复刻。

## 9. 部署建议

- 小程序：微信平台发布，生产构建强制真实 AppID、HTTPS 域名和主体信息。
- API：容器化单服务起步，Caddy 提供自动 HTTPS，后续按实际负载拆分。
- 数据库：托管 PostgreSQL，启用自动备份与时间点恢复。
- 媒体：对象存储与 CDN，不通过 API 服务进程转发大文件。
- 环境：开发、测试、生产三套配置隔离。
- 交付：CI 执行测试和镜像构建；容器提供就绪探测、优雅停机、只读文件系统和非 root 运行。
